# ADR-003: 混合类型数据结构必须类型感知访问

**日期**: 2026-06-14 ~ 2026-06-18
**状态**: 已采纳

## Context

`state.clues` 数组同时存储 `string`（线索 ID）和 `{ id, name }`（线索对象）。
这种混合类型导致多个 bug：

- NPC 秘密叙事文本被当线索 ID 塞入 `s.clues`
- `CONSUME_ARCHIVE` 中 `pop()` 返回对象，拼入字符串显示 `[object Object]`
- `isAreaUnlocked` 用 `.includes()` 无法匹配对象元素

## Decision

1. 混合类型数组的查找必须用类型感知函数（`hasClueId`），不能用 `includes`
2. 从数组 pop/取出的值，拼入字符串前必须检查类型
3. NPC 数据中的 `secrets` 是叙事文本，不是线索 ID——代码注释应标明数据格式
4. Setter 函数应内置 clamp——不依赖调用方的记忆力
5. 复合字符串协议必须按完整已知后缀解析，不能假设最后一个下划线是字段分隔符；例如 `NPC_memory_trigger` 的操作名本身含下划线，应优先匹配 `_memory_trigger`、`_trust±N` 等完整模式

## Consequences

- ✅ 线索面板显示正确
- ✅ 区域解锁检测正确
- ✅ 减少类型检查遗漏
- ⚠️ 需要维护类型感知的访问函数而非直接用数组方法
- ⚠️ 历史紧凑字符串格式应集中在适配器中解析，并用对象格式作为新数据的首选协议

## 2026-08-09 补充：线索 source 是复合证据协议

`clue_chains[].clues[].source` 并非单一事件 ID，现有数据同时包含事件、稳定线索 ID、NPC 信任门槛、物品名和 `A + B` 合取条件，且少量历史条目使用“封印仪式残页”等叙事别名。

- 只能通过集中的 `isEvidenceSatisfied` 适配器判定，不得将 `source` 直接与 `triggeredEvents` 比较。
- NPC 信任同时兼容显示名与稳定 ID；物品必须先走 item registry 规范化。
- 叙事别名只在该适配器内建立到真实事件/物品生产者的映射。
- 旧章节事件的 `effects.items` 与新协议 `add_item` 都必须进入统一效果适配器；“数据校验能解析物品”不代表运行时已将它发放给玩家。

回归测试必须使用真实的港口、莫里斯和异端线索链，覆盖复合 source 和稳定 NPC ID，不得只测手写简化链。

## 2026-08-10 补充：事件触发条件必须经过章节与 NPC 身份适配器

章节事件数据使用数字 `trigger.chapter` 表示“最低可用章节”，不是精确章节，也不能用“第一周/之后”二分法代替。运行时必须通过统一的日数→章节映射判断：早期章节事件允许在后续继续出现，但未来章节事件不得提前进入候选池。第 4、8、15、22 天边界必须分别覆盖章节 2～5；回归测试还必须使用至少一个真实第五章事件，证明它在第 8 天不可用、第 22 天可用。

事件数据中的 `npc_trust_gte`、`npc_alive`、`npc_dead` 仍可能使用中文显示名，而新状态和迁移后存档使用稳定 NPC ID。所有事件触发器（扩展与 legacy fallback）必须通过集中的 NPC 状态访问器读取，优先稳定 ID，同时兼容显示名和旧存档键；不得直接使用 `state.npcTrust[authoredName]` 或 `state.npcStates[authoredName]`。

事件系统测试必须导入生产触发器，禁止复制一份简化 `checkTrigger` 作为被测实现，否则测试会与旧错误逻辑一起通过。

## 2026-08-10 补充：章节门控与文本变换必须保持统一协议

区域的 `chapter_1_role` 只描述第一章中的呈现方式，不是永久锁定标志；实际开放时间必须复用 `chapterReducer.isChapterUnlocked` 的日数→章节映射。不得在地图工具中另写 `day > 7` 一类边界，否则第三、四章区域会永久不可达。移动按钮必须从玩家当前区域计算邻接关系，不能用目标区域的邻接表判断目标是否连接自己。

文本碎片化管线中的句子集合必须始终保持为字符串或词数组，原地修改型 helper 的返回值不能直接塞入集合。回归测试至少覆盖低 SAN、短句和中途重置分支，确保后续拼句阶段不会收到 `undefined`。

共享 `GD.events` 是只读定义库，任何只属于本次 action 的衍生内容都必须先复制。低 SAN 虚假选项不能直接 `push` 到事件定义的 `choices`；应复制事件与 choice 数组，把运行时候选只存入 `pendingChoice`。否则第一轮会永久污染事件池，后续同 seed 回放仍会因为候选数量和 RNG 消耗不同而分叉。确定性审核必须在同一进程内连续跑两次相同 seed，单独启动两个进程无法暴露这种定义污染。

Legacy 效果适配器的已知字段表与执行分支必须成对注册；把 `remove_item` 写进内容但未注册，会出现叙事说“交换了手电筒”、背包却没有扣除的静默失效。真实事件回归应同时断言奖励与代价，而不只断言新增资源。

同一个内容效果不能同时在事件 ID 特判与通用适配器中执行；例如码头风险降低迁入通用 `harbor_night_risk_reduction` 后，原事件特判必须只保留反馈文本，否则效果会叠加两次。发布游玩审计应捕获 `[applyLegacyEffects]` 未识别字段警告并作为失败，控制台告警不能出现在“PASS”之后而不进入 JSON 报告。

事件 choice 的展示协议允许只有 `label` 而没有 `text`。选择结果叙事必须按 `choice.text → choice.label → 通用兜底` 解析，禁止把可选字段直接传给 `c.narr`。同理，`investigation_bonus` 等历史顶层效果要在通用适配器中落到正式状态字段（这里是有期限的 `tempSkillBonus`），事件 ID 特判只负责独特反馈文本。

NPC 兼容不能只做读取适配。所有 `npc_trust`、`npc_changes` 和 typed effect 写入必须先解析稳定 ID，并以“稳定 ID 优先、显示名仅作旧存档回退”的规则读取旧值；写回时删除同一 NPC 的旧显示名影子键。死亡、腐化、日程可见性和结局条件也必须通过同一访问器，否则会出现奖励已触发但数值未生效、已死亡 NPC 仍出现等静默分叉。

对话弹窗中的派生候选同样不能只在 `TALK_NPC` 打开时计算一次。`NPC_RESPONSE` 推进或完成追问线程后，必须用已提交的 `npcThreads` 与最新信任值重新构建 `pendingNpc.availableThreads`；否则已完成按钮会继续显示并产生无限静默 no-op。候选构建器应由打开与响应两个路径共享，禁止复制两套深度/分支判断。

信任门槛和线索链必须做依赖方向检查：如果某条线索需要 NPC 信任 5 才能产生，那么“升到信任 5”的 gate 不能反过来要求先完成包含该线索的整条链。最高信任门槛应依赖玩家已能获得的表层线索/前置物品，链完成则作为后续结果；回归测试要验证无完整链时仍存在一条可达路径。
