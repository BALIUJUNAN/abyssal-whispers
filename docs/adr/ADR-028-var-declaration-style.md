# ADR-028: 项目统一使用 var 声明

**日期**: 2026-07-02
**状态**: 已采纳

## Context

项目 93/145 源文件（2083 处）使用 `var` 作为模块级声明关键字，无 ADR 记录此选择。
`const`/`let`（ES2015）提供块级作用域，在现代 JS 项目中更为常见。
v0.2.2 dailySlice 饥饿系统 bug 由 `var` 在循环中的 hoisting 行为导致。

## Decision

统一使用 `var` 作为模块级声明关键字：

1. **Hoisting 行为一致** — `var` 的函数级作用域和提升行为在模块顶层（严格模式下的模块作用域）表现一致，避免 `const`/`let` 的 TDZ（暂时性死区）陷阱
2. **历史一致性** — 项目从非 ESM 时代演进，`var` 是原始选择；全面切换为 `const`/`let` 成本高、收益低（模块顶层声明，块级作用域优势不明显）
3. **已知代价可接受** — v0.2.2 bug 由 `var` hoisting 在循环中导致，已通过代码审查机制防范（循环内声明需显式检查作用域）

## Consequences

- ✅ 项目声明风格统一，无需在每个文件中选择 `var`/`const`/`let`
- ✅ 避免 TDZ 相关错误（`const`/`let` 在声明前访问会抛 ReferenceError）
- ⚠️ `var` hoisting 在循环中可能产生意外行为（v0.2.2 教训），需代码审查注意
- ⚠️ 新贡献者可能对 `var` 全项目使用感到意外（CLAUDE.md 已记录此惯例）
